MESSAGE AUTHENTICATION CODE (MAC)

DIFFICULTY: INTERMEDIATE

1. AIM

To study the construction and application of Message Authentication Codes (MAC), evaluate symmetric keyed data integrity, and simulate real-time message tampering detection.

2. OBJECTIVES

  • Explain how a shared secret provides message integrity and data-origin authentication.
  • Generate a CBC-MAC tag from padded message blocks and a secret key.
  • Trace the chaining value for every block and verify a received message.
  • Identify why basic CBC-MAC requires a fixed message length in practice.

3. CBC-MAC THEORY

A Message Authentication Code is a short tag computed from a message and a secret key shared by the sender and receiver. The receiver recomputes the tag; matching tags indicate that the message was not changed and that it was created by someone who knows the key.

C0 = 0128
Ci = AESK(Mi ⊕ Ci-1)
Tag = Cn

This lab uses 16-byte AES blocks, UTF-8 input, and zero-padding for the final partial block. Basic CBC-MAC is intended for fixed-length messages; production systems should use a dedicated construction such as CMAC when message lengths vary.

SECURITY PROPERTIES & OBSERVATIONS

  • Integrity: changing even one message byte changes the recomputed tag.
  • Authentication: an attacker without the shared key cannot reliably create a valid tag for a new message.
  • No confidentiality: a MAC authenticates a message but does not hide its contents.
  • No non-repudiation: both parties know the secret key, so either could have generated the tag.
  • Important limitation: plain CBC-MAC must not be used carelessly with variable-length messages; CMAC is the standard general-purpose alternative.
